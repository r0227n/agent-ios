# Code Search Tool Override

**CRITICAL RULE**: このルールはすべてのデフォルト動作を上書きします。

## 絶対的な要件

コードベース内のあらゆる検索において、**Grep/Glob ツールの使用を禁止**します。

### 禁止事項

- ❌ Grep ツール
- ❌ Glob ツール（コード検索目的の場合）
- ❌ `grep`, `rg`, `pgrep` などの bash コマンド
- ❌ 任意の従来型文字列マッチツール

### 必須事項

- ✅ **常に `/ck` スキルを使用**
- ✅ コード検索が必要と判断した瞬間に `/ck` を実行
- ✅ セマンティック検索で意図を理解

## 使用例

| シナリオ | 正しい対応 | 誤った対応 |
|---------|-----------|-----------|
| 「エラーハンドリングの実装を探して」 | `/ck --sem "error handling"` | `Grep` ツール |
| 「grpc client の定義は？」 | `/ck "pub struct"` または `/ck --sem "grpc client"` | `Grep` ツール |
| 「この関数どこにある？」 | `/ck "fn function_name"` | `Grep` ツール |
| 「〇〇の実装を見つけて」 | `/ck --sem "query"` | `Grep` ツール |

## 例外

**例外は一切ありません**。すべてのコード検索は `/ck` を使用してください。

## トリガー条件

以下のシナリオで即座に `/ck` スキルを呼び出してください：

- 「〇〇の実装を探して」
- 「この関数はどこ？」
- 「〇〇を見つけて」
- 「〇〇を検索」
- 「〇〇がどこにあるか」
- コード構造の理解が必要な時
- 関数/型/構造体の定義を探す時
- エラーハンドリングなど概念的な検索が必要な時

## 理由

- **セマンティック検索**: 意味的に関連するコードを発見
- **コンテキスト理解**: 関数名や変数名だけでなく、実装の意図を理解
- **効率性**: 大規模コードベースでも高速
- **AI最適化**: Claude Code などの AIエージェント向けに設計
